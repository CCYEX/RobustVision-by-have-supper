# 指标词典
本项目所有 md 文件里出现过的指标的含义。


## 一、检测效果类（"找得准不准"）

### GT（Ground Truth，真值/标注）

- 数据集中人工标注的目标边界框与类别，作为评测的参照标准。
- **本项目**：BDD100K 的 box2d 标注，筛出 10 类驾驶目标（labels10 口径）。

### IoU（Intersection over Union，交并比）
- 预测框与真值框交集与并集面积之比，取值 [0,1]，是判定 TP 的阈值标准。
- **本项目**：评测匹配阈值 0.5；mAP50-95 则在 0.5~0.95 共 10 档阈值下综合计算。

### 置信度（confidence，conf）
- 检测头输出的该框含目标且类别正确的概率估计（经 sigmoid 归一化的分数）。
- **本项目**：评测时全部保留（不过滤），缓存进 parquet 后再按条件/阈值分析。

### TP / FP / FN
- 真正例（True Positive）（预测为真，实际为真）、假正例（False Positive）（预测为真，实际为假）、假反例（False Negative）（预测为假，实际为真）。
- **本项目**：按 IoU 阈值与类别匹配判定；一个真值只能被"认领"一次，重复认领的算 FP。

### P（Precision，查准率/精确率）
- P = TP / (TP + FP)，衡量判断准不准。
- **本项目**：M0 在 clean_day 上 P=0.7137，即每报 100 个框约 71 个是对的。

### R（Recall，查全率/召回率）
- R = TP / (TP + FN)，衡量判断漏掉的多不多。
- **本项目**：M0 在 clean_day 上 R=0.484，即 100 个真目标约漏掉 52 个（检测任务召回天然偏低，因为小目标和遮挡多）。

### PR 曲线（Precision-Recall Curve）
- 把置信度门槛从 1 慢慢降到 0，每个门槛下算一次 P 和 R，连成的曲线。门槛高 → 报得少但准（P 高 R 低）；门槛低 → 报得多但杂（R 高 P 低）。曲线越鼓（越靠右上角）越好。


### AP（Average Precision，单类平均精度）
- 某一类目标（比如"car"）的 PR 曲线下面积，综合了查准和查全，单一类别在所有召回水平上的精度积分（实践中按置信度排序逐点累加）。


### mAP50（mean Average Precision @ IoU 0.5）
- 框只要和答案重合一半以上（IoU≥0.5）就算对，在这个标准下，所有类别 AP 的平均值。


### mAP50-95（= 表里的 mAP / map，主指标）
- 把标准从"重合一半就算对"逐级收紧到"重合 95% 才算对"（0.5, 0.55, …, 0.95 共 10 档），每档各算一个 mAP 再平均。**框画得糙不糙也计入成绩**，所以比 mAP50 严格得多、数值也低得多。这是整个项目的主指标。
- **本项目**：M0 clean_day 0.3022、night 0.2231；M2 night 0.2546。全部阶梯表数字都是它。

### 分数换算（0.30 = "30 分"）
- 口语里说"掉了 3 分" = mAP 绝对值变化 0.03；"掉 30%" = 相对变化 30%（rel_drop，见下）。本项目文档里"分"一律指前者（绝对 0.01 = 1 分），"%"指后者。

### 混淆矩阵（Confusion Matrix）
- 一张"对答案"表格——每行是真类别，每列是模型判的类别，对角线上的数字越多越准。能看出模型把"rider"认成"person"这类具体错误。
- **本项目**：`results/training/m*_confusion_matrix.png`（三模型各一张，Ultralytics 训练时自动产出）。

## 二、置信度校准类

检测分数回答"找得准不准"；校准回答另一个正交问题：**模型自报的置信度是不是诚实的**。

### 置信度校准（Calibration）
- 预测置信度与经验正确频率的一致程度。模型说"我 80% 确定"的那批预测，实际是不是真有 8 成是对的？是 → 校准好；实际只有 6 成 → 过度自信；实际有 9 成 → 保守。


### 匹配打标签（校准的前置步骤）
- 把每个检测框和真值按 IoU≥0.5 配对（一个真值只能配一次），配上 = 这框"对"（标签 1），配不上 = "错"（标签 0）。于是几十万个检测框变成几十万道"对/错"的判断题，才能统计置信度诚不诚实。


### logit
- sigmoid 逆变换前的实值输出 z，sigmoid(z) ∈ (0,1) 即置信度。

### 温度缩放 / 温度 T（Temperature Scaling）
- p' = sigmoid(logit / T)，单参数在留出校准集上以最小化 NLL 求得（bounds 0.05–10，标量优化）。T>1 = 整体调低自信，T<1 = 整体调高自信。因单调性不变排序，检测指标不变。
- **本项目**：M0 T=0.762（<1 → 原模型偏保守/不够自信，与文献中"网络普遍过自信"相反）；M2 T=0.8076。校准集 2,999 张 clear-day。

### NLL（Negative Log-Likelihood，负对数似然）
- -Σ [y·log p + (1-y)·log(1-p)]，二元交叉熵；优化目标。

### ECE（Expected Calibration Error，期望校准误差，15 桶）
- **校准的主指标**。把所有检测按自信度分进 15 个桶（0~0.1 一桶、0.1~0.2 一桶…），每桶里比一比"平均自信度"和"实际答对率"差多少，再加权平均。0 = 完美诚实。0.08 大概是"说八成把握的，实际只对七成"这种量级的偏差。

- **本项目**：M2 clean_day ECE 0.0842 → 0.0775（校准后相对下降 8.0%）；snow 0.0812 → 0.0658（−19.0%）。

### MCE（Maximum Calibration Error，最大校准误差）
- 15 个桶里**最差那一桶**的偏差。

- **本项目**：M2 fog MCE 0.496→0.636（样本仅 92 个检测，波动大）。

### Brier 分数（Brier Score）

- **mean[(p − y)²]**：一种给"概率预测"打分的方法——每道题按 (自信度 − 对错)² 罚分再平均。比 ECE 更平滑（不依赖分桶方式），两个一起看更稳。
- **本项目**：M2 clean_day 0.1195 → 0.1169（越小越好）。

### 可靠性图（Reliability Diagram）
- ECE 的可视化版。横轴 = 嘴上说的把握，纵轴 = 实际答对率，每个桶一个点。点落在对角虚线上 = 诚实；整体在上方 = 保守（说 0.6 实际对 0.8），在下方 = 吹牛。蓝色实线是校准前，红色虚线是校准后，**红线比蓝线更贴对角线 = 校准有效**。
- **本项目**：`results/calibration/m*/reliability.png`，每模型一张、7 个条件面板。右下角多余空面板为布局占位。

### 保险丝检查（monotone check）
- 温度缩放为严格单调变换，抽样验证 logit 排序逐位不变。

## 三、项目协议类（我们自己定的口径）

### clean_day（晴天白天，基准条件）
- BDD100K 属性 weather=clear ∧ timeofday=daytime 的测试子集，共 1,235 张；合成损坏也以它为底图（成对参照）。

### rel_drop（相对掉分）
- 相对基准条件的 mAP 变化率（%）。

### 自然偏移平均 / 合成损坏平均
- 把 13 个测试条件分成两组分别算平均分——**自然组**（夜/雨/雪/晨昏，路上真实会遇到的）看真实泛化，**合成组**（7 种人工像素损坏，stress test）看抗干扰极限。分组平均防止"合成条件好练"掩盖"真实条件没进步"。
- **本项目**：自然组 M0 0.2668 → M2 0.2822（+1.4 分）；合成组 M0 0.2538 → M1 0.2723（M1 主场，+1.9 分）。

### 阶梯差值 Δ（M1−M0、M2−M1）
- 控制变量设计下的逐级差分（数据是唯一变量：seed/架构/超参/起点权重全同）。"M1−M0 = 这一步合成增强的净收益"；"M2−M1 = 加真实夜间数据的净收益"。因为三个模型除数据外一切配置相同，差值就是因果归因。

### severity 2（文件名里的 `_s2`）
- 合成损坏的"用力程度"分 0~5 档（COCO-C/imagenet-c 惯例的 5 级标度），我们统一用第 2 档——中等强度，模拟真实传感器退化，不至于把图毁得连人都看不出来的程度。

### 其他(undefined)（校准报告里的兜底桶）
- BDD100K 里一部分图天气/时段属性缺失或写不出名字，单独归成一桶统计，**不混进任何命名条件里充数**，保证 6 个命名条件的口径纯净。

### labels10 口径
- 只考 10 类驾驶目标（person…traffic sign），BDD 标注里其他任务的面条线（车道线等）不参与计分。

### fog 仅 9 张（样本量警示）
- 自然雾测试图只有 9 张，雾的结论主要看合成雾（fog_s2，1,235 张）。

## 四、训练过程类（训练日志/曲线图里的词）

### epoch（轮）
- 一次完整训练集迭代。M0/M1 各 40 轮上限，M2 30 轮。


### patience = 15（早停耐心）
- early-stopping 容忍轮数。连续 15 轮验证分数不再进步就自动停，防止空烧显卡。

### batch = 8（批大小）
- 每步前向/反向的样本数，每次一起塞给显卡 8 张图算梯度。三个模型统一用 8 保证可比。

### AMP（混合精度）
- 让显卡一半时间用FP16/FP32 自动混合精度训练，省显存又提速，精度几乎不损。

### it/s（张/秒）
- 训练速度——每秒处理几张图。

### seed = 42（随机种子）
- 全局随机种子，控制数据抽样与训练随机过程。

### box_loss / cls_loss / dfl_loss（三条训练损失曲线）
- 训练时模型犯的三类错，各罚一笔分：**box** = 框画歪了罚多少；**cls** = 类别认错了罚多少；**dfl** = 框边缘画得犹豫不决罚多少。三条曲线都应一路下降然后走平。


### COCO 预训练 + 微调（fine-tune）
- 先拿已经在 33 万张通用图上毕了业的模型（yolo11m.pt），再用我们的驾驶数据迁移学习。三个模型用同一份起点权重，保证起点公平。

### best.pt / last.pt
- best = 模拟考考得最好那一轮存的档；last = 最后一轮的档（用于断点续训）。**所有评测和发布都用 best.pt**。

### imgsz = 640
- 输入统一缩放到 640×640 训练与评测（三模型一致）。
